# DreamTexture for Unreal ChangeLog

## Unreleased

### Fixed

- **Closing the editor could crash while closing the event stream.** In a project where nothing else loads the
  `WebSockets` module early (the stock Launcher editor does, through the default `OnlineSubsystem` plugin), it was first
  loaded by this plugin's event stream, so it was unloaded before the plugin; closing the stream on shutdown then tried
  to load it again and hit an engine assertion. The plugin now loads `WebSockets` and `HTTP` when it starts, so they are
  unloaded after it, and never touches an unloaded `WebSockets` module.

## 0.9.0 - 2026-10-13

First public release. It is a beta: the behavior below is tested, but interfaces and generated asset layout may still change before 1.0.

> Push from Web, Reflow, and the CHORD seamless switch need a DreamTexture backend that has the editor session
> and push endpoints, the `src-upload-v1` image segment, `derived_from` on `POST /api/generate`, the `tileable`
> parameter and the CHORD wrap-padding switch. These are on the backend's `master` branch. On an older backend the
> affected features turn themselves off and say why. See [Backend](Docs/backend.md#which-backend-version).

### Added

- **Browse the backend's library in the editor and import a set with one click.** The *DreamTexture* panel under
  *Tools* opens on the **Library** page: search (0.3 seconds after you stop typing), filter by style, favorites only,
  paged loading. Selecting a set shows its prompt, seed, resolution and tags. Sets made with CHORD are
  marked *Research use only*, and sets whose base image came from a cloud model are marked as not reproducible with the same
  parameters. A material the web UI has just finished appears in the list by itself (on `job.done`).
- **Importing a set produces correctly configured textures.** They land in
  `/Game/DreamTexture/<name>_<id tail>/T_<name>_<id tail>_<BC|N|ORM|H>`. Compression and sRGB follow the
  manifest's color space and channel: Base Color sRGB, Normal `TC_Normalmap`, ORM `TC_Masks`, Height `TC_Grayscale`.
  Separate Roughness, Metallic and AO are not imported by default (the ORM covers them); a setting turns them on.
  16-bit grayscale PNGs stay 16-bit.
- **Importing the same set again downloads nothing and creates nothing.** Each texture records its source (material id,
  channel, sha256) in the package metadata. Channels whose hash is unchanged are skipped; changed ones are updated in
  place, so materials already using them stay connected. The records live only in editor data and are not cooked.
- **Normals are not flipped.** Both backend pipelines already output DirectX normals. The green channel is flipped
  only when a manifest states `y: opengl`.
- **Every download is verified.** Each texture is checked for size, then for sha256 (the first 16 hex digits of the
  SHA-256 of the whole file, as the backend computes it) before it is written. A partial or mismatching file is never
  taken for a good one.
- **A notification when an import finishes, with a jump to the Content Browser.** It appears even if the panel is closed,
  and reports created, updated and unchanged textures, the material instance, and the license.
- **A material instance you can drag onto a mesh, after every import.** Each set gets `MI_<name>` (built or updated in
  place), whose parent is `M_DreamTexture_Master`, generated by the plugin: ORM sampled once, normal strength,
  roughness range, AO strength, UV tiling, and optional parallax occlusion mapping (off by default). When a texture is
  missing, the matching static switch is turned off and a fallback value is used, instead of sampling a default texture.
- **The master material is generated by code into your `/Game` folder, not stored in the plugin.** It keeps working when
  the plugin is disabled or removed (tests read the saved `.uasset`'s name table to confirm it does not reference the
  plugin), and the repository has no binary assets. When the graph changes it is rebuilt in place as the same asset by
  version number, so existing instances stay connected. A material of your own at that path is left untouched, and is
  never cleared. Usage flags for skeletal meshes, instanced meshes and Nanite are preset.
- **Assign to the selected objects in one step.** Actors selected in the level (anything with a mesh component) or a
  static mesh selected in the Content Browser: the dialog first says *N material slots will be replaced*, lets you choose a
  slot on multi-slot meshes, and the whole assignment is one transaction, undone with one Ctrl+Z. Meshes that ship with the
  engine (including those in engine plugins) are never modified.
- **Generate in the editor.** The new **Generate** page: image model x decompose model, prompt and *Refine prompt*,
  resolution, 1 to 8 variants, seed (capped to stay inside 2^53), optional cloud base image with model and quality.
  Progress follows the same event stream as the web UI, and a dropped stream catches up on reconnect. Optional
  *Import automatically when done*. A combination whose output cannot be used commercially (CHORD) is marked before submitting,
  and the import notification states the license.
- **The plugin can start the backend for you.** The **Connection Status** page has *Start Backend*, *Stop Backend* and *Open Web UI*.
  If a backend already answers on the port, the plugin attaches to it and only ever stops the one it started. The child
  process is tied to a Windows Job Object, so a crashed editor leaves no background process behind. Optional start
  with the editor (off by default, since ComfyUI takes VRAM). When the backend is down and an executable is set,
  the Generate button becomes *Start backend and generate*.
- **Send to UE from the web UI.** On a material's page, one click makes it appear in a running editor (a choice of
  editor when several are online; the backend's MCP interface has a tool of the same name). A push is not lost when the
  editor's event stream happens to be down: the heartbeat after reconnecting redelivers it, and it is imported only once.
- **Reflow: send a material from your project to the backend and bring the result back.** The new **Reflow** page takes any
  material, or the material slot of an actor. For every texture it recognizes the channel, with evidence ordered from
  most to least reliable: provenance record, material graph wiring, parameter name, asset name, sampler type. You can correct a
  result by hand and it is remembered per material. It exports PNGs from source data and says why when it cannot (it never
  falls back to a compressed mip 0). Then:
  - **Fill missing channels** decomposes only the Base Color and returns the missing Normal, Roughness, AO and Height. The new
    instance's Base Color points at **your original texture**, not a re-encoded round trip.
  - **Restyle** uses the Base Color as a reference image, repaints it from a prompt, and decomposes the full set.
  - By default the result becomes a new set of textures and an instance. *Overwrite in place* edits the selected material
    instance, only for the ticked channels, in one undo step. It is unavailable for a master material, which has no
    parameters to change.
- **UV-unwrapped textures (characters, props, trim sheets) get their own route.** With *UV-unwrapped* selected, the request
  does no seamless processing, the decompose model defaults to Classic derivation instead of CHORD (CHORD stays selectable,
  with a warning, because UV-unwrapped images are out of its distribution), the restyle denoise strength has a hard cap of
  0.35 (more would destroy the UV correspondence), and the preview is *original | result* side by side. The choice is remembered
  per material in `Saved/DreamTexture`, not written into your assets.
- **Documentation, license and release tooling.** MIT license, English and Chinese README, a `Docs/` manual, an English
  changelog, a localization toolchain that builds the Simplified Chinese translation without opening the editor (see
  *Changed*), and a GitHub workflow that packages the plugin source on a version tag.

### Changed

- **The interface is English with a Simplified Chinese translation.** Text follows the editor language, including the
  plugin's page in *Project Settings* (names, tooltips and categories). Messages from the Client and Assets modules are
  localized as well, and so are the job stages the backend reports (*Submitting*, *Generating*, ...). Other text that
  comes from the backend — error messages, ComfyUI reasons, model names, environment check items — is shown as the
  backend wrote it, which today is Chinese.

### Fixed

- **The environment check callback could run twice.** When a request could not be sent (for example an empty
  address), UE 5.8's `ProcessRequest()` calls the completion callback once, synchronously, before returning false,
  and the old code called it again on the return value.
- **Closing the editor could crash while unregistering the push session.** The settings object was read on the
  module shutdown path, after the GUI editor had already torn down the UObject system. The unregister call now
  uses the backend address cached when the session was registered.

### Verified

- **The connection acceptance of the first build was run for real.** Against a fixture backend: connected in 0.1 seconds;
  *backend up, ComfyUI down* is shown correctly; stopping the backend leaves *Connected* after 1.4 seconds and is judged
  unreachable after 4.4; after the backend was stopped long enough for the backoff to reach its cap, restarting it and
  reconnecting by itself took 6.5 seconds without clicking *Reconnect*. The 40-second watchdog path (a half-open connection)
  is not covered by a test.
- **About 200 automated tests across the editor, with extra groups for the real pipeline.** `Tools/Test.ps1 -Render` compiles every
  switch combination of the master material under a real RHI and renders a 3x3 tiled preview; `-Pipeline` starts an isolated
  ComfyUI and backend (refusing to start with less than 10 GiB of free VRAM, and never touching your own) and generates and
  reflows for real, down to which texture a material instance parameter points at.

## 0.1.0 - 2026-09-05

### Added

- **Plugin skeleton and a connection to the backend.** Two modules: `DreamTextureClient` (REST, WebSocket and a connection state
  machine, with no dependency on editor UI) and `DreamTextureEditor`. It reconnects after a drop, using the backoff and the
  silence threshold already proven by the web UI (1000 to 15000 ms backoff, 40-second watchdog).
- **The DreamTexture panel, with three separate status levels.** Backend process, event stream and ComfyUI are shown apart.
  While ComfyUI is cold-starting the panel says *Starting (N s)* instead of *Not connected*.
